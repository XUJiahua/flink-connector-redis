# Redis connector 2.2.6.2-pre

本预发布版基于 v2.2.6.1 维护线，修复低流量下 Redis Sink 尾部记录仅在后续输入或 checkpoint 到达时才发送的问题。构建基线为 Java 11、Flink 2.2.1。用于测试和灰度验证，不包含 v2.2.7 至 v2.2.10 的后续改动。

## 变更

- 使用 Flink processing-time 定时器，从当前批次首条记录入队时开始计时；即使没有后续输入，缓冲也会按 `sink.batch.flush-interval` 主动发送。
- 满批、checkpoint 和关闭会取消并使旧定时回调失效；普通与 limited Sink V2 路径均接入定时服务。
- 异步 Redis 命令明确失败时，通过 mailbox 通知静默任务；保留 QPS 限流、in-flight 背压和 checkpoint 确认等待。
- 新增 `redis_sink_oldest_buffer_age_ms`，实时观察未发送记录的等待年龄。
- 新增可控时间回归、真实 Flink 集成测试及独立 Docker Redis 一键验收脚本。

## 验证

64 项相关测试通过，包含真实 Flink 2.2.1 与 Redis 7.4.7：

- `batch.size=1 / interval=60000ms`：104ms 后读到单条写入。
- `100 / 1000ms`，关闭 checkpoint、单条后静默：1096ms 后读到写入，任务仍运行。
- `100 / 60000ms`，100 条同 key 更新：126ms 后读到最终值。
- WRONGTYPE 异步错误：静默作业在约 1132ms 内失败。
- Redis 暂停 600ms：Writer checkpoint 刷新等待 637ms 后返回。
- 真实断连：Writer checkpoint 刷新在 60 秒后报超时；连接恢复后待确认写入仍执行成功。

以上为本地单次观察，不是生产延迟承诺。完整步骤与边界见[验收记录](https://github.com/XUJiahua/flink-connector-redis/blob/v2.2.6.2-pre/docs/design/sink-timed-flush.md)。

## 使用和限制

建议先保持 `sink.batch.size=1` 验证 jar 兼容性，再小范围恢复 `100 / 1000ms`。`flush-interval=0` 禁用定时刷新。保留的旧七参数 Writer 构造器没有独立定时服务，直接调用方需迁移到新构造器；SQL / Table API 已接入新路径。

一秒刷新不保证一秒业务可见或一秒故障判定。checkpoint 超时不代表写入已取消；恢复连接后仍可能执行待确认命令。本次不增加事务或 exactly-once。

两个独立作业写同 key 时，旧累计快照仍可覆盖较新快照，本地已复现。跨作业版本保护、生产窗口 SQL、真实读取链路、峰值负载和双机房网络仍需单独验收。
